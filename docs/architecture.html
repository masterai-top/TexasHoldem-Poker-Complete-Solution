Unity 客户端与 C++ 游戏服务端架构

基于仓库公开结构整理的组件边界和部署关注点，不替代实际源代码审计。

本页内容客户端服务端数据层请求链路

Unity 移动客户端

Unity 与 C# 负责牌桌、俱乐部、赛事、个人中心和互动界面。仓库还包含 Android SDK、iOS Workspace、资源依赖配置和编辑器工具目录。

C++ 实时游戏服务

根目录中的 C++ 模块覆盖游戏开始与结束、房间消息、客户端消息、下注、弃牌、全下、自动操作、计时和数据库访问等职责。

职责代表性模块
游戏生命周期gamebegin、gameend、gameroot
实时消息onclientmessage、onroommessage、sendroommessage
玩家动作allin、autobet、autofold
数据访问DBOperator、订单和服务配置模块

MySQL 与 Redis

项目说明将 MySQL 用于持久化存储，将 Redis 用于缓存和会话管理。上线前应确认表结构、索引、连接池、主从策略、缓存失效、备份恢复和数据保留政策。

典型请求链路

  1. Unity 客户端建立认证和实时通信连接。
  2. C++ 服务端校验玩家、房间和牌局状态。
  3. 状态机处理玩家动作并向牌桌参与者广播结果。
  4. MySQL 保存需要持久化的数据，Redis 维护缓存与短期状态。
  5. 运营服务读取经过授权的数据用于用户、订单和排行榜工作流。
公开仓库结构不能证明生产环境的完整安全性或并发能力。部署前必须完成代码、协议、依赖和基础设施验收。
